# Отчёты ГУАП на suai-report

suai-report — пакет XeLaTeX (`suai-report.sty`) и команда `suai`. Пакет сам
ставит всё оформление по ГОСТ 7.32-2017: титул по бланку ГУАП, поля, шрифт,
заголовки, подписи, нумерацию. В `main.tex` пишется только текст и короткие
блочные команды `\suai…`. Поэтому почти вся работа — это содержание отчёта:
понять задание, разобрать скриншоты, честно и ясно описать сделанное.

## Порядок работы

### 1. Осмотреться

- Найди папку отчёта. Обычно это `Предмет/lab-N/`; готовый PDF назовётся
  `Предмет-lab-N.pdf` (по двум папкам).
- Что в ней лежит: методичка (PDF/DOCX), `images/` со скриншотами, `code/`
  или исходники, данные (xlsx, csv), уже начатый `main.tex`.
- Прочитай `main.tex` соседнего отчёта (обычно предыдущей лабы того же
  предмета), но **только если он на suai-report v2.6**. Это видно по
  `build/main.log` (`Package: suai-report … v2.6`) или по
  `.vscode/settings.json` со строкой `suai_copy`;
  `check_report.py` на старом отчёте сам напишет «собрано на v2.x».
  Такой отчёт — лучший образец: оттуда видно, как пользователь пишет
  введение, подписи, заключение и источники, и какие данные стоят в
  титуле. Подстраивайся под этот стиль, а не под свой.
- Отчёты до v2.6 за образец не бери: в них устаревший синтаксис
  (`\begin{code}`, ручные `tabular`, `\allowbreak` в ячейках). Если рядом
  нет отчётов на 2.6, пиши по этому скиллу.

### 2. Создать отчёт, если `main.tex` ещё нет

```bash
cd Предмет/lab-4 && suai next --no-open          # создаст ../lab-5 с титулом из lab-4
suai new Предмет/lab-5 --title "Название работы" --no-open
```

`suai new` берёт титул из самого свежего соседнего отчёта, номер — из имени
папки (`lab-5` → 5), ставит `date = today`, создаёт `images/`, `.vscode/`,
`.gitignore`. Если папка уже есть и в ней лежат материалы — это нормально,
`suai new` их не трогает (падает, только если `main.tex` уже есть).
`--no-open` — чтобы не открывать VS Code; убери его, если пользователь
хочет сразу живой предпросмотр.

Если команды `suai` нет, проверь пакет: `kpsewhich suai-report.sty`. Без
пакета отчёт не соберётся — скажи пользователю, что нужен
`git clone https://github.com/Echways/suai-report && make install`.
Заготовку `main.tex` без `suai` — см. `references/commands.md`, раздел «Заготовка».

Данные титула, которых нет ни в соседнем отчёте, ни в методичке
(преподаватель, его должность, кафедра), не выдумывай: оставь как есть
и пометь `% TODO: проверить`, потом перечисли такие места пользователю.

### 3. Прочитать задание

Методичку читай целиком (PDF — инструментом Read, по 20 страниц). Выпиши:
цель, задачи / пункты порядка выполнения, вариант, требования к содержанию
отчёта. Если методичка задаёт структуру отчёта — она главнее структуры
по умолчанию ниже. Контрольные вопросы в отчёт не входят, если о них не
просили.

### 4. Разобрать скриншоты

Открой **каждый** файл в `images/` (инструментом Read) и запиши для себя:
что на нём, к какому пункту задания относится, какие на нём видны данные
(значения, имена, результаты). Подписи и текст пишутся по тому, что реально
изображено, а не по имени файла: `ris07.png` ничего не говорит, а под
рисунком должно стоять «Документ „Поступление товаров и услуг“, закладка
„Товары“». Порядок рисунков в отчёте — порядок выполнения работы (обычно
совпадает с порядком имён файлов). Если скриншот не подходит ни к одному
пункту — спроси или упомяни в конце, но не вставляй молча.

### 5. Написать `main.tex`

Структура лабораторной по умолчанию:

```latex
\maketitle
\suaitoc

\suaiintro
Цель работы~--- … (из методички, своими словами можно, смысл тот же)

\suaitasks
задача из методички, с маленькой буквы, без точки в конце
ещё задача

Вариант, исходные данные, среда выполнения — абзацем, если есть.

\section{Ход работы}
\subsection{…}            % по подразделу на пункт задания
…
\suaiconclusion
…
\suaisources
Методические указания …
```

Курсовая: `type = Курсовая работа`, `number = ,` (пусто), обычно
`course-label = по дисциплине:`, главы — `\section`, свои структурные
элементы без номера — `\suaisection{Вариант задания}`.

Как писать сам текст — в `references/writing.md`. Прочитай его перед
первым отчётом в разговоре: там стиль, оформление чисел, ссылки, подписи,
заключение и источники.

### 6. Собрать и проверить

```bash
cd Предмет/lab-5 && suai build                       # PDF: Предмет-lab-5.pdf
python3 <папка-скилла>/scripts/check_report.py .     # проверки ниже
```

`check_report.py` читает `main.tex` так же, как пакет v2.6, и берёт
`build/main.log`. Вывод делится на четыре части:

- **ОШИБКИ** — исправить: битая ссылка (с подсказкой похожей метки),
  нет файла рисунка или листинга, язык не из установленного listings,
  `%` в строке блока, блок без пустой строки перед `\end{…}`, формула с
  пробелами в ячейке, ошибки сборки. Ошибку внутри блока TeX
  показывает строкой конца блока, скрипт допишет, с какой строки блок
  начался.
- **ПРЕДУПРЕЖДЕНИЯ** — просмотреть: объекты без ссылки или раньше неё,
  забытые скриншоты, строки таблицы с другим числом ячеек, текст шире
  поля, ручные `figure`/`tabular`/`itemize`, устаревший лог.
- **TODO** — строки с `TODO`, их надо перечислить пользователю.
- **ИТОГ** — страницы, число рисунков, таблиц, листингов и имя PDF: это
  готовые данные для отчёта пользователю.

Код выхода 1 — есть ошибки. Скрипт можно запускать и до сборки: то, что
её уронит, он покажет понятнее, чем лог.

Если сборка остановилась, сначала запусти скрипт. Если он не нашёл
причину, ищи первую строку вида `./main.tex:42: …` в `build/main.log`.
Частые причины — в таблице ловушек ниже.

### 7. Посмотреть на PDF

```bash
pdftoppm -r 60 -png -f 1 -l 4 Предмет-lab-5.pdf /tmp/page   # потом Read
```

Глянь титул, содержание и страницы с таблицами и листингами: не съехали ли
столбцы, не стоит ли рисунок раньше ссылки на него, нет ли пустых строк
вместо данных. Достаточно нескольких страниц, не всего отчёта.

### 8. Отчитаться

Коротко: где PDF, сколько страниц, рисунков и таблиц, и **что пользователю
надо проверить** — все `% TODO`, места, где не хватило данных (например,
результаты, которых нет на скриншотах), скриншоты, которые ты не стал
вставлять.

## Синтаксис: главное правило

**Блочная команда читает строки под собой до пустой строки.** Каждая строка
становится пунктом списка, строкой таблицы, пояснением к формуле или
источником. Блок также кончается на строке, начинающейся с `\suai…`,
`\section`, `\begin`, `\clearpage`, но **не** с `\end`: перед `\end{…}`,
в том числе перед `\end{document}` после `\suaisources`, всегда нужна
пустая строка, иначе сборка падает. Код под `\suaicode` пишется
**с отступом** и кончается на первой непустой строке без отступа.

| Команда | Что делает |
| --- | --- |
| `\suaiintro`, `\suaiconclusion` | «Введение», «Заключение» (без номера, с новой страницы) |
| `\suaisection{Название}` | другой ненумерованный элемент |
| `\suaitasks` | «Для достижения поставленной цели…» + задачи а), б) |
| `\suaienum` / `\suailist` / `\suainum` | список а) б) / через дефис / 1) 2) |
| `\suaitable[метка]{Название}` | таблица, ячейки через `\|`, первая строка — шапка |
| `\suaiimg[ширина]{файл}{Подпись}[метка]` | рисунок из `images/`, метка `fig:файл` |
| `\suaieq[метка]{формула}` | формула; строки `обозначение \| смысл` дают «где …» |
| `\suaicode[язык, метка]{Подпись}` | листинг, код строками с отступом ниже |
| `\suaicode[язык]{файл}{Подпись}` | листинг из файла (ищется и в `code/`), метка `lst:файл` |
| `\suaisources` | список источников, по одному на строку |
| `\suaiapp[справочное]{Название}` | приложение А, Б… |
| `\figref`, `\tabref`, `\lstref`, `\formref` | «рисунке 1», «таблице 1», «листинге 1», «формуле (1)» |

Подробно, с примерами и настройкой под методичку — `references/commands.md`.

## Ловушки (по частоте)

| Что сделать | Почему |
| --- | --- |
| Пункт списка и строку таблицы — **на одной строке**, сколь угодно длинной | Перенос строки = новый пункт / новая строка таблицы |
| После блока — пустая строка | Иначе следующий абзац станет ещё одним пунктом или строкой |
| Пункты с маленькой буквы, без `;` и `.` в конце | Пунктуация ставится сама; `\suailist*` — без неё |
| В ячейках и тексте экранировать `% $ & # _` | Это обычный LaTeX; `%` без `\` обрежет строку таблицы |
| Никаких `% комментариев` в строках блока | `%` съедает перевод строки: следующая строка приклеится, пустая строка не закроет блок |
| Формула в ячейке — без пробелов: `$a+b$`, `$\lvert{}x\rvert$` | В v2.6 `$a + b$` в `\suaitable` роняет сборку («Missing $»); в тексте, списках и `\suaieq` пробелы можно |
| Символ `\|` внутри ячейки — `\textbar{}` | `\|` — разделитель ячеек |
| В `\suaicode` ничего не экранировать, отступ ≥ 1 пробела, после `{Подписи}` на той же строке пусто | Код читается как есть; подпись — это LaTeX, в ней `\_` нужен |
| Язык листинга — только из списка listings | Неизвестный язык (`yaml`, `json`, `javascript`, `rust`, `kotlin`, `dockerfile`) **роняет сборку**; для них — без языка: `\suaicode[label=lst:имя]{…}` |
| Одна картинка дважды — 4-й аргумент `[метка]` у второй | Иначе две метки `fig:файл` |
| Ссылка — `на~\figref{x}`, `в~\tabref{x}`, `по~\formref{x}` | `\figref` даёт форму «рисунке 1»; для «рисунок 1», «рисунки 1–3» — `рисунок~\ref{fig:x}` |
| Не писать `\begin{figure}`, `tabular`, `itemize`, `lstlisting` руками | Блочные команды дают ГОСТ-оформление и метки; ручное — только если команда не умеет |

Доступные языки listings: `Python`, `bash`, `sh`, `SQL`, `C`, `C++`,
`Java`, `PHP`, `HTML`, `XML`, `Go`, `R`, `Matlab`, `Octave`, `Pascal`,
`Delphi`, `VBScript`, `Haskell`, `Ruby`, `Perl`, `TeX`, `make`, `Fortran`,
`Lisp`, `Prolog`, `VHDL`, `Verilog`, `gnuplot`, `Awk`, `erlang`, `Scala`,
`Swift`, `Lisp`, `csh`, `ksh`, `tcl`, `Scilab`; с диалектом — ключом:
`\suaicode[language={[Sharp]C}, label=lst:x]{…}`, `{[x86masm]Assembler}`,
`{[Visual]Basic}`, `{[5.3]Lua}` (без диалекта Lua, Assembler и Basic
роняют сборку). Полный список — в установленном listings, по нему же
сверяет `check_report.py`.

## Чего не делать

- Не выдумывать результаты, числа, выводы программы и содержимое экранов,
  которых нет ни на скриншотах, ни в данных. Нет данных — `% TODO` и
  вопрос пользователю.
- Не переписывать методичку: теория — коротко и своими словами, ровно
  столько, чтобы было понятно, что и зачем сделано.
- Не трогать `.vscode/` и `build/`, не менять преамбулу без причины
  (настройки под методичку — исключение, см. `references/commands.md`).
